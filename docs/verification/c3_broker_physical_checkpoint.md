## 首次联网结果与诊断

初次串口实际出现 `ESP_MQTT_LAB_ONLY` 启动标记与 91 条资源状态。180 秒就绪等待失败：末次状态为 `wifi=0`、`trusted=0`、`state=0`、`outbox=0`，Broker 没有该实验设备的客户端连接。`wifi_connect_error=0` 只证明 SDK 接受连接请求，不能证明取得 IP。没有执行或计为通过 QoS、动态订阅和百次生命周期矩阵。

本轮 Wi-Fi 输入来自刚读取的历史 Flash 中通过字段和长度验证的 v1 配置页，版本为 5，仅投影为私有实验输入；该操作不是持久数据迁移，也不能证明这个网络现在可达。当前宿主的网络扫描将 SSID 隐去，既有受管公司网络参数也与该历史输入不同，因此尚不能自行确定可用的实验网络参数。已向维护者请求设备附近可用的 2.4 GHz 网络与受控凭据位置。

独立样例新增 `wifi_disconnect_reason` 原因码输出，只记录 SDK 数值，不记录 SSID、密码或地址。它用于定位真实接入点／认证故障，保留 RAM Wi-Fi 行为和严格 TLS 前置条件。

诊断改动已在固定 SDK 下完成 C3 与 ESP32 的原生编译／链接，C3 沿用本轮私有输入，ESP32 使用空实验输入。C3 应用为 956544 B，SHA-256 为 `5646899876fb4fa8a9d2276cf2b7648150d7f4228dff827d7320378543642a92`；ESP32 应用为 900320 B，SHA-256 为 `3aba4f5a2182c21f87cc901e9850f35b582edcae5a2d84366979aa4389d003fb`。构建参与的样例源码摘要与本提交逐字节对应，编译成功本身不证明取得 IP 或联网。
